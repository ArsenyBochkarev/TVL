Нужно ввести конфигурацию программы. Конфигурация -- это пара `<T, Q>`, где
- `T` -- это множество потоков в программе. В каждом потоке может встретиться текущее состояние потока. Состояние потока -- это пара `{A, P}`, где
    - `A` -- текущий актор
    - `P` -- набор команд, которые актор должен выполнить
- `Q` -- словарь (map) словарей очередей сообщений к каждому из существующих в программе акторов. Сообщение характеризуется своим названием `M`. Доступ к элементам:
    - `Q[A]` -- словарь очередей к актору `A` от всех акторов
    - `Q[A][B]` -- очередь сообщений к актору `A` от актора `B`

*Нотация:*
- *Последовательное исполнение: символ `;`*
- *Пустая команда: символ `ε`*
- *Список: `head :: tail`*
- *Ограничение на размер канала (очереди сообщений к какому-то актору от другого актора): `MAX_QUEUE_SIZE`*

Все правила ниже пытаются примениться недетерминированною на каждом состоянии конфигурации.

1. Посылка сообщений
    - В голову очереди сообщений к актору `B` от актора `A` добавляется сообщение `M`
    - ```
		Q[B][A] < MAX_QUEUE_SIZE   Q[B][A] == Q_b_a
		———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
	    <{A, send M to B; P} ∪ T, Q ∪ Q[B][A]> --> <{A, P} ∪ T, Q ∪ Q[B][A](Q_b_a <- Q_b_a :: M)> `
	  ```
2. Получение сообщений
    - Одиночное получение сообщения:
        - В голове очереди сообщений к актору `A` от актора `B` содержится сообщение `M`
        - ```
			Q[A][B] == M :: Q_a_b
			———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
			<{A, receive M from B; P} ∪ T, Q ∪ Q[A][B]> --> <{A, P} ∪ T, Q ∪ Q[A][B](M :: Q_a_b <- Q_a_b)>
	      ```
    - Получение одного из возможных сообщений:
        - В голове очереди сообщений к актору `A` от актора `B_i` содержится одно из `N` возможных сообщений `M_i`
        - ```
			∃B_b: Q[A][B_b] == M :: Q_a_b_j   M == M_j_b
			————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————
			∀b=0..N, ∀i=0..I, ∀j=0..J∀, k=0..K: <{A, receive alts { M_0_0 from B_0 => { P_0_0 } ... M_i_0 from B_0 => { P_i_0 } ... M_I_0 from B_0 => { P_I_0 } ... M_0_b from B_b => { P_0_b } ... M_j_b from B_b => { P_j_b } ... M_J_b from B_b => { P_J_b } ... M_0_N from B_N => { P_0_N } ... M_k_N from B_N => { P_k_N } ... M_K_N from B_N => { P_K_N }; P } ∪ T, Q ∪ Q[A][B_i]> --> <{A, P_j_b; P} ∪ T, Q ∪ Q[A][B_j](M :: Q_a_b_j <- Q_a_b_j)>
	  	  ```
          - `otherwise`: если в момент прихода в `receive alts` в очередях сообщений нет ни одного подходящего сообщения, то берём эту ветку
          - ```
            ∀j=0..N Q[A][B_0] == K_0 :: Q_a_b_0 ... Q[A][B_j] == K_i :: Q_a_b_j ... Q[A][B_N] == K_N :: Q_a_b_N   ∀t=0..N, ∀b=0..N, ∀i=0..I, ∀j=0..J∀, k=0..K K_t != M_0_0 ... K_t != M_i_0 ... K_t != M_I_0 ... K_t != M_0_b ... K_t != M_j_b ... K_t != M_J_b ... K_t != M_0_N ... K_t != M_k_N ... K_t != M_K_N
            ————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————
            ∀b=0..N, ∀i=0..I, ∀j=0..J∀, k=0..K: <{A, receive alts { M_0_0 from B_0 => { P_0_0 } ... M_i_0 from B_0 => { P_i_0 } ... M_I_0 from B_0 => { P_I_0 } ... M_0_b from B_b => { P_0_b } ... M_j_b from B_b => { P_j_b } ... M_J_b from B_b => { P_J_b } ... M_0_N from B_N => { P_0_N } ... M_k_N from B_N => { P_k_N } ... M_K_N from B_N => { P_K_N } otherwise => { P_other }; P } ∪ T, Q> --> <{A, P_other; P} ∪ T, Q>
            ```
3. Недетерминированный выбор
    - `∀i=0..N <{A, choose { P_0 } or ... or { P_i } or ... or { P_N }; P } ∪ T, Q> --> <{A, P_i; P} ∪ T, Q>`
4. Цикл
    - "Бесконечный" цикл:
      - Ожидаем `break` для выхода
      - Делаем шаг вычисления в теле, а также сохраняем тело цикла как параметр в `repeat`
      - ```
          <{A, P_1} ∪ T, Q> --> <{A, P_1'} ∪ T, Q'>
          ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
          <{A, repeat { P_1 }; P} ∪ T, Q> --> <{A, repeat [P_1] { P_1' }; P} ∪ T, Q'>
        ```
      - Исходный параметра тела сохраняется при шаге вычисления в теле
      - ```
            <{A, P_1} ∪ T, Q> --> <{A, P_1'} ∪ T, Q'>
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_0] { P_1 }; P} ∪ T, Q> --> <{A, repeat [P_0] { P_1' }; P} ∪ T, Q'>
        ```
      - Перезапускаем цикл, взяв тело из параметра
      - `<{A, repeat [P] { ε }; P} ∪ T, Q> --> <{A, repeat { P }; P} ∪ T, Q'>`
   - Конечный цикл:
      - Аналогично прошлому варианту, но со счётчиком
      - Не просто синтаксический сахар, т.к. хотим поддержать для него `break`
      - ```
            N > 0   <{A, P_1} ∪ T, Q> --> <{A, P_1'} ∪ T, Q'>
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat N { P_1 }; P} ∪ T, Q> --> <{A, repeat [P_1] N-1 { P_1' }; P} ∪ T, Q'>
        ```
      - ```
            N > 0   <{A, P_1} ∪ T, Q> --> <{A, P_1'} ∪ T, Q'>
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_0] N { P_1 }; P} ∪ T, Q> --> <{A, repeat [P_0] N-1 { P_1' }; P} ∪ T, Q'>
        ```
      - ```
            N == 0
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat N { P_1 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>
        ```
   - `break`:
      - Должен обеспечить выход из цикла без выполнения кода после себя
      - Без `repeat` не должен работать
      - `<{A, repeat N { break; P_2 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
      - `<{A, repeat N [P_1] { break; P_2 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
      - `<{A, repeat { break; P_2 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
      - `<{A, repeat [P_1] { break; P_2 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
5. Параллелизм
    - Что доступно к выполнению, то и запускается
    - Дожидаемся, пока каждая из веток закончит свою работу (придёт в `ε`)
    - ```
		∀j=0..N <{A, P_0} ∪ T, Q> --> <{A, P_0'} ∪ T, Q_0'> ... <{A, P_j} ∪ T, Q> --> <{A, P_j'} ∪ T, Q_j'> ... <{A, P_N} ∪ T, Q> --> <{A, P_N'} ∪ T, Q_N'>
		———————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————— 
		∀i=0..N <{A, parallel { P_0 } and ... and { P_i } and ... and { P_N }; P } ∪ T, Q> --> <{A, parallel { P_0 } and ... and { P_i' } and ... and { P_N }; P} ∪ T, Q>
	  ```
    - `∀i=0..N <{A, parallel { ε } and ... and { ε } and .. and { ε }; P } ∪ T, Q> --> <{A, P} ∪ T, Q>`
    - `skip`:
        - Полностью пустое действие
        - `∀i=0..N <{A, parallel { P_0 } and ... and { skip; P_i } and ... and { P_N }; P } ∪ T, Q> --> <{A, parallel { P_0 } and ... and { P_i } and ... and { P_N }; P } ∪ T, Q>`
