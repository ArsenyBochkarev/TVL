Нужно ввести конфигурацию программы. Конфигурация -- это пара `<T, Q>`, где
- `T` -- это множество потоков в программе. В каждом потоке может встретиться текущее состояние потока. Состояние потока -- это пара `{A, P}`, где
    - `A` -- текущий актор
    - `P` -- оставшаяся последовательность команд, которые актор должен выполнить
- `Q` -- словарь (map) словарей очередей сообщений к каждому из существующих в программе акторов. Сообщение характеризуется своим названием `M`. Доступ к элементам:
    - `Q[A]` -- словарь очередей к актору `A` от всех акторов
    - `Q[A][B]` -- очередь сообщений к актору `A` от актора `B`

Каждому актору соответствует ровно один поток. В `<{A, P} ∪ T, Q>` множество `T` содержит остальных акторов, которые в данный момент не делают шагов. Завершённая программа `ε` не имеет шага. Изначально акторы содержат свои исходные программы, а все очереди пусты.

*Нотация:*
- *Последовательное исполнение: символ `;`*
- *Пустая команда: символ `ε`*
- *Очередь: `head :: tail`, где `head` -- первый элемент, а `tail` -- остаток. Пустая очередь: `[]`. Записью `q <- q :: M` обозначается добавление сообщения `M` в конец очереди `q`, и замену исходной очереди на обновлённую. Запись `|q|` означает длину очереди `q`*
- *Ограничение на размер канала (очереди сообщений к какому-то актору от другого актора): `MAX_QUEUE_SIZE`*
- *Символ `-->` обозначает шаг актора*
- *Символ `#` обозначает комментарии внутри правила*

Актор доступен к исполнению тогда и только тогда, когда имеет шаг. Завершение означает, что все остаточные программы акторов равны `ε`, даже если в очередях остались сообщения. Состояние тупика соответствует отсутствию доступных к исполнению акторов, и незавершенности хотя бы одного актора.

Все правила ниже пытаются примениться недетерминированно на каждом состоянии конфигурации.

1. Посылка сообщений
    - В конец очереди сообщений к актору `B` от актора `A` добавляется сообщение `M`
    - ```
		|Q[B][A]| < MAX_QUEUE_SIZE   Q[B][A] == Q_b_a
		———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
	    <{A, send M to B; P} ∪ T, Q ∪ Q[B][A]> --> <{A, P} ∪ T, Q ∪ Q[B][A](Q_b_a <- Q_b_a :: M)> `
	  ```
   - Если в очереди сообщений не хватает места -- ждём, пока место освободится
   - Для неотрицательного целого `N` команда `send N M to B` означает `N` последовательных примитивных отправок. Это отдельные шаги, допускающие чередование, каждый с проверкой ёмкости канала. Группа отправок не является атомарной. `send 0 M to B` означает `skip`. Если количество опущено, выполняется одна отправка.
2. Получение сообщений
    - Одиночное получение сообщения:
        - В голове очереди сообщений к актору `A` от актора `B` содержится сообщение `M`
        - ```
			Q[A][B] == M :: Q_a_b
			———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
			<{A, receive M from B; P} ∪ T, Q ∪ Q[A][B]> --> <{A, P} ∪ T, Q ∪ Q[A][B](M :: Q_a_b <- Q_a_b)>
	      ```
        - Получить можно только сообщение из головы очереди, иначе ветвь исполнения блокируется. Сообщения в глубине очереди не проверяются.
        - Для неотрицательного целого `N` команда `receive N M from B` означает `N` последовательных примитивных получений, каждое из которых может блокироваться и чередоваться с другими шагами; группа не атомарна. `receive 0 M from B` означает `skip`. Если количество опущено, выполняется одно получение.
    - Получение одного из возможных сообщений:
        - Ветви исполнения при получении одного из возможных сообщений `M_i from B_i => { P_i }` нумеруются конечными индексами `i ∈ I = {0, ..., N}`. Команда множественного получения `receive alts` обозначается `alts(I)`, а при наличии `otherwise => { P_other }` -- как `alts(I, P_other)`.
        - Множество индексов ветвей с доступными для получения сообщениями: `E(A,Q,I) = { i ∈ I | ∃q: Q[A][B_i] == M_i :: q }`. Можно выбрать любую доступную ветвь без приоритета по порядку записи или отправителю. Проверка отправителя и сообщения, удаление головы и выбор ветви составляют один атомарный шаг. Тело ветви может начать выполнение на следующем шаге, затем может выполняться `P`.
        - ```
            i ∈ E(A,Q,I)   Q[A][B_i] == M_i :: q
            ————————————————————————————————————————————————————————————————————————————————————————————————————————————
            <{A, alts(I) ∪ P_i; P} ∪ T, Q ∪ Q[A][B_i]> --> <{A, P_i; P} ∪ T, Q ∪ Q[A][B_i](M_i :: q <- q)>
          ```
        - ```
            i ∈ E(A,Q,I)   Q[A][B_i] == M_i :: q
            ————————————————————————————————————————————————————————————————————————————————————————————————————————————
            <{A, alts(I, P_other) ∪ P_i; P} ∪ T, Q ∪ Q[A][B_i]> --> <{A, P_i; P} ∪ T, Q ∪ Q[A][B_i](M_i :: q <- q)>
          ```
        - `otherwise`: берём эту ветвь тогда и только тогда, когда в момент выполнения шага нет доступных ветвей получения. Пустые очереди и неподходящие головы одинаково считаются недоступными. Проверка и выбор ветви атомарны. Без `otherwise` пустое множество доступных ветвей блокирует эту ветвь исполнения.
        - ```
            E(A,Q,I) == ∅
            ————————————————————————————————————————————————————————————————————————————————————————————————————————————
            <{A, alts(I, P_other); P} ∪ T, Q> --> <{A, P_other; P} ∪ T, Q>
          ```
3. Пустая команда
  - Полностью пустое действие
  - `<{A, skip; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
4. Недетерминированный выбор
    - `∀i=0..N <{A, choose { P_0 } or ... or { P_i } or ... or { P_N }; P } ∪ T, Q> --> <{A, P_i; P} ∪ T, Q>`
5. Цикл
    - "Бесконечный" цикл:
      - Ожидаем `break` для выхода
      - При первом входе в тело цикла, оно сохраняется как параметр в `repeat`. Все последующие итерации цикла производятся с уже сохранённым параметром. Формы с квадратными скобками используются для обозначения параметра во время исполнения и не входят в исходный синтаксис языка.
      - ```
          <{A, P_0} ∪ T, Q> --> <{A, P_1 } ∪ T, Q'>     # Внутренний шаг вычисления из P_0 в P_1
          ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
          <{A, repeat { P_0 }; P} ∪ T, Q> --> <{A, repeat [P_0] { P_1 }; P} ∪ T, Q>
        ```
      - Исходный параметр тела сохраняется при шаге вычисления в теле
      - ```
            <{A, P_1} ∪ T, Q> --> <{A, P_2} ∪ T, Q'>     # Внутренний шаг вычисления из P_1 в P_2
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_0] { P_1 }; P} ∪ T, Q> --> <{A, repeat [P_0] { P_2 }; P} ∪ T, Q'>
        ```
      - Перезапускаем цикл, взяв тело из параметра: `<{A, repeat [P] { ε }; P} ∪ T, Q> --> <{A, repeat [P] { P }; P} ∪ T, Q>`
   - Конечный цикл:
      - Аналогично прошлому варианту, но со счётчиком
      - Исходный счётчик — неотрицательное целое число. В `repeat [P_0] N { P_1 }` число `N > 0` обозначает оставшиеся итерации, включая текущую. Шаги тела сохраняют его, и только завершение итерации уменьшает счётчик.
      - Не просто синтаксический сахар над `N` командами подряд, т.к. для него поддержан `break`
      - Начальная итерация:
      - ```
            N > 0   <{A, P_0} ∪ T, Q> --> <{A, P_1 } ∪ T, Q'>     # Внутренний шаг вычисления из P_0 в P_1
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat N { P_0 }; P} ∪ T, Q> --> <{A, repeat [P_0] N { P_1 }; P} ∪ T, Q>
        ```
      - Итерация при нескольких оставшихся исполнениях (параметр сохраняется):
      - ```
            N > 0   <{A, P_1} ∪ T, Q> --> <{A, P_2} ∪ T, Q'>     # Внутренний шаг вычисления из P_1 в P_2
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_0] N { P_1 }; P} ∪ T, Q> --> <{A, repeat [P_0] N { P_1 }; P} ∪ T, Q'>
        ```
      - При попытке входа в цикл с нулём предполагаемых итераций, семантика эквивалентна `skip`:
      - ```
            N == 0
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_0] N { ε }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>
        ```
      - При завершении итерации восстанавливаем сохранённое тело или выходим после последней итерации:
      - ```
            N > 1
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_0] N { ε }; P} ∪ T, Q> --> <{A, repeat [P_0] (N-1) { P_0 }; P} ∪ T, Q>
        ```
      - `<{A, repeat [P_0] 1 { ε }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
   - `break`:
      - Должен обеспечить выход из цикла без выполнения кода после себя
      - Выходит из ближайшего внешнего `repeat` или `parallel`. Конструкции `choose` и `receive alts` не создают область действия `break`. Без обеих внешних конструкций `break` некорректен и не имеет шага.
      - ```
            N > 1
            ———————————————————————————————————————————————————————————————————————————————————————————————————————————— 
            <{A, repeat [P_1] N { break; P_2 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
        ```
      - `<{A, repeat [P_1] { break; P_2 }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
6. Параллелизм
    - Что доступно к выполнению, то и запускается
    - Конструкция `parallel` дожидается, пока каждая из веток закончит свою работу (придёт в `ε`)
    - `parallel` внутри `parallel` запрещён
    - Это статическое ограничение, включая вложенность через циклы или выбор. Шаг требуется только выбранной ветви; заблокированные или завершённые соседние ветви ему не мешают.
    - ```
		i ∈ 0..N   <{A, P_i} ∪ T, Q> --> <{A, P_i'} ∪ T, Q_i'>     # Внутренний шаг вычисления из P_i в P_i'
		———————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————————— 
		<{A, parallel { P_0 } and ... and { P_i } and ... and { P_N }; P } ∪ T, Q> --> <{A, parallel { P_0 } and ... and { P_i' } and ... and { P_N }; P} ∪ T, Q_i'>
	  ```
    - `∀i=0..N <{A, parallel { ε } and ... and { ε } and .. and { ε }; P } ∪ T, Q> --> <{A, P} ∪ T, Q>`
    - `break`:
        - Экстренно обрывает все ветви исполнения
        - `∀i=0..N <{A, parallel { P_0 } and ... and { break; P_i } and ... and { P_N }; P} ∪ T, Q> --> <{A, P} ∪ T, Q>`
        - Выходит из ближайшей параллельной области, отменяет остальные её ветви и переходит к её продолжению. Выход не имеет приоритета над доступными шагами соседних ветвей.
