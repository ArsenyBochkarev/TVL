Сообщение -- именованная константа `Message`. Глобальное состояние -- это словарь (map) словарей очередей сообщений к актору: `Q: map[String, map[String, List[Message]]]`. Ключи -- имена акторов.

*Нотация*:
- *`;` -- последовательное исполнение*
- *`-->` -- логическое следование*
- *`->` -- обозначение ребра*
- *`:=` -- изменение состояния*
- *`nil` -- пустая программа. При встрече в `effect` означает тождественную функцию `Q := Q`*
- *`MAX_QUEUE_SIZE` -- ограничение на размер каналов*
- *Инструкции `repeat`, `repeatN` и `parallel` хранят внутреннее состояние: исходное тело и остаток текущей итерации цикла, его счётчик либо остатки параллельных ветвей.*
- *Очередь: `head :: tail`, где `head` -- первый элемент, а `tail` -- остаток. Пустая очередь: `[]`. Записью `q <- q :: M` обозначается добавление сообщения `M` в конец очереди `q`, и замену исходной очереди на обновлённую. Запись `|q|` означает длину очереди `q`.*

Каждый актор -- это кортеж `(S, S0, L, T, F)`, где:
- `S` -- множество возможных состояний актора
  - Состояние `s` актора `A` -- вся остаточная программа, включая продолжение, сохранённые тела и счётчики циклов, остатки параллельных ветвей
- `S0` -- множество начальных состояний актора
- `L` -- функция разметки. Связывает состояние со свойствами актора
- `T` -- множество возможных переходов. Переход -- это кортеж `(s, cond, effect, n)`, где
  - `s` -- текущее состояние актора
  - `cond` -- условие перехода
  - `effect` -- функция, модифицирующая глобальное состояние `Q`
  - `n` -- следующее состояние актора ("∃ ребро из `s` в `n`")
  - `stepInsideScope(inst, s)` -- множество локальных рёбер `(s, g, e, s')` для остатка `s` внутри `repeat`, `repeatN` или `parallel`. Выбирается одно ребро, и его условие `g` и эффект `e` переносятся во внешнее ребро без изменений.
  - Условия проверяются на текущем `Q`. Эффект применяется атомарно с переходом. Недоступная инструкция и `nil` не имеют локальных рёбер ожидания.
  - Варианты переходов:
    - Send:
      - `s` = `send M to B; s'`
      - `cond` = `Q == Q_other ∪ Q[B][A]   |Q[B][A]| < MAX_QUEUE_SIZE   Q[B][A] == Q_b_a`
      - `effect` = `Q := Q_other ∪ Q[B][A](Q_b_a <- Q_b_a :: M)` (добавили в конец сообщение `M`)
      - `n` = `s'`
    - Receive:
      - `s` = `receive M from B; s'`
        - `cond` = `Q == Q_other ∪ Q[A][B]   Q[A][B] == M :: Q_a_b` (сообщение `M` в начале очереди к `A` из `B`)
          - `n` = `s'`
          - `effect` = `Q := Q_other ∪ Q[A][B](M :: Q_a_b <- Q_a_b)`
      - При пустой очереди или другой голове перехода нет. В `parallel` это блокирует только текущую ветвь, если другая ветвь может сделать шаг.
    - Receive alts:
      - Ветви индексируются `i = 1..N`: `(M_i, B_i, s_i)`.
      - Пусть `E(A,Q) = {i | ∃q: Q[A][B_i] == M_i :: q}` -- множество индексов доступных ветвей этой инструкции.
      - Без `otherwise`:
        - `s` = `receive alts { M_1 from B_1 => { s_1 } ... M_N from B_N => { s_N } }; P`
        - Получили сообщение:
          - `cond` = `i ∈ E(A,Q)   Q == Q_other ∪ Q[A][B_i]   Q[A][B_i] == M_i :: q`
          - `effect` = `Q := Q_other ∪ Q[A][B_i](M_i :: q <- q)`
          - `n` = `s_i; P`
        - Не получили сообщение: при `E(A,Q) = ∅` перехода нет.
      - Существует `otherwise`:
        - `s` = `receive alts { M_1 from B_1 => { s_1 } ... M_N from B_N => { s_N } otherwise => { s_other } }; P`
        - Получили сообщение (аналогично предыдущему случаю):
          - `cond` = `i ∈ E(A,Q)   Q == Q_other ∪ Q[A][B_i]   Q[A][B_i] == M_i :: q`
          - `effect` = `Q := Q_other ∪ Q[A][B_i](M_i :: q <- q)`
          - `n` = `s_i; P`
        - Не получили ни одно из доступных сообщений:
          - `cond` = `E(A,Q) = ∅`
          - `effect` = `nil`
          - `n` = `s_other; P` (перешли в состояние из `otherwise` ветки с продолжением)
      - Любая доступная ветвь выбирается недетерминированно, без приоритета порядка записи или отправителя, в том числе при одинаковых парах сообщения и отправителя. Проверка текущих голов очередей, выбор ветви и удаление выбранного сообщения -- один атомарный шаг.
    - Choose:
      - ∃ `N` переходов, `∀i=1..N`:
        - `s` = `choose { s_1 } or ... or { s_N }; P`
        - `cond` = `true`
        - `effect` = `nil`
        - `n` = `s_i; P`
    - Repeat:
      - Три варианта:
        - В начале сохраняем тело цикла, как внутренний параметр для инструкции `repeat`, а также делаем шаг вычисления
          - `s` = `repeat { s_1 }; P`
          - Для каждого ребра `(s_1, g, e, s_1') ∈ stepInsideScope(repeat, s_1)`:
            - `cond` = `g(Q)`
            - `effect` = `e`
            - `n` = `repeat [s_1] { s_1' }; P`
        - Аналогично, но для цикла с уже сохранённым параметром:
          - `s` = `repeat [s_body] { s_i }; P`
          - Для каждого ребра `(s_i, g, e, s_i') ∈ stepInsideScope(repeat, s_i)`:
            - `cond` = `g(Q)`
            - `effect` = `e`
            - `n` = `repeat [s_body] { s_i' }; P`
        - Когда сохранён параметр, и текущая итерация цикла завершилась, цикл перезапускается:
          - `s` = `repeat [s_body] { nil }; P` (в текущей итерации цикла не осталось действий)
          - `cond` = `true`
          - `effect` = `nil`
          - `n` = `repeat [s_body] { s_body }; P` (пользуемся параметром и заново выставляем тело цикла)
    - Repeat N:
      - Пять вариантов, аналогично варианту выше, но с возможностью выхода по окончанию счётчика
      - Не просто синтаксический сахар, т.к. для него поддержан `break`
      - Исходный счётчик -- целое `N ≥ 0`; во внутренней форме `N > 0` считает оставшиеся итерации, включая текущую. Шаги тела не уменьшают счётчик.
        - В начале сохраняем тело цикла, как внутренний параметр для инструкции `repeat`, а также делаем шаг вычисления
          - `s` = `repeat { s_1 }; P`
          - Для каждого ребра `(s_1, g, e, s_1') ∈ stepInsideScope(repeat, s_1)`:
            - `cond` = `g(Q)`
            - `effect` = `e`
            - `n` = `repeat [s_1] { s_1' }; P`
        - Аналогично, но с сохранённым параметром:
          - `s` = `repeat [s_body] N { s_i }; P`
          - Для каждого `(s_i, g, e, s_i') ∈ stepInsideScope(repeatN, s_i)` при `N > 0`:
            - `cond` = `g(Q)`
            - `effect` = `e`
            - `n` = `repeat [s_body] N { s_i' }; P`
        - Когда сохранён параметр, и текущая итерация цикла завершилась, цикл перезапускается с уменьшением счётчика:
          - `s` = `repeat [s_body] N { nil }; P`
          - `cond` = `N > 1`
          - `effect` = `nil`
          - `n` = `repeat [s_body] (N-1) { s_body }; P`
        - После последней итерации:
          - `s` = `repeat [s_body] 1 { nil }; P`
          - `cond` = `true`
          - `effect` = `nil`
          - `n` = `P`
        - Нулевой исходный счётчик (тело не выполняется):
          - `s` = `repeat 0 { s_1 }; P`
          - `cond` = `true`
          - `effect` = `nil`
          - `n` = `P`
    - Break:
      - Два варианта выхода из циклов после их инициализации:
        - Без счётчика, запомненное тело:
            - `s` = `repeat [s_body] { break; s_1 }; P`
            - `cond` = `true`
            - `effect` = `nil`
            - `n` = `P`
        - Со счётчиком, запомненное тело:
          - `s` = `repeat [s_body] N { break; s_1 }; P`
          - `cond` = `N > 0`
          - `effect` = `nil`
          - `n` = `P`
      - Самостоятельного ребра у `break` нет, вне областей `repeat`, `repeat N` или `parallel` он недопустим. Исходный цикл сначала инициализируется. `repeat 0` пропускает тело, включая `break`.
    - Parallel:
      - `s` = `parallel { s_1 } and ... and { s_i } and ... and { s_N }; P`
      - Исполнение может продвигаться дальше:
        - Для любого `i = 1..N` и каждого `(s_i, g, e, s_i') ∈ stepInsideScope(parallel, s_i)`:
          - `cond` = `g(Q)`
          - `effect` = `e`
          - `n` = `parallel { s_1 } and ... and { s_i' } and ... and { s_N }; P` (продвижение по текущей ветке)
        - Продвигается одна ветвь, остальные не меняются. Заблокированные и завершённые (`nil`) ветви не препятствуют шагу другой ветви.
      - Исполнение всех веток `parallel` завершилось:
        - `cond` = `∀i=1..N. s_i = nil`
        - `effect` = `nil`
        - `n` = `P`
      - Встретили `break` в одной из ветвей:
        - `cond` = `∃i=1..N, R. s_i = break; R`
        - `effect` = `nil`
        - `n` = `P`
        - Отменяются все ветви. Выход не имеет приоритета перед шагом другой ветви. Цикл внутри `parallel` сначала обрабатывает собственный `break`, не выходя из внешнего параллельного исполнения.
      - Вложенные `parallel` запрещены.
    - Skip:
      - `s` = `skip; P`
      - `cond` = `true`
      - `effect` = `nil`
      - `n` = `P`
- `F` -- множество конечных состояний: `{s ∈ S | s = nil}`
